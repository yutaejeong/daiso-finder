다이소 파인더 · 검색 로그 분석

검색 결과가 “0건”으로 끝나는 검색,
어떤 패턴이고 어떻게 줄일 수 있을까

검색어 로그 시트(2026-09-12 ~ 2026-11-11, 검색 47,176건)를 전부 내려받아 0건이 나온 검색을 분류하고, 실제 다이소 검색 API에 표본 질의를 다시 던져 “질의를 조금만 고치면 찾을 수 있었는지”를 확인했습니다.

웹에서 이루어진 검색의 절반가량이 0건이고, 9주 동안 거의 변하지 않았습니다. 대부분은 “정말 없는 것”이 아니라 검색 방식과 사용자의 입력이 어긋나서 생깁니다.

핵심 발견
  • 매장 검색은 ‘이름·주소의 글자 일치’로 동작합니다. 띄어쓰기가 들어가면 97%, ‘다이소’가 들어가면 100%, 영문이면 98%가 0건입니다. 한글 1~2글자 지명(‘명동’, ‘강남’)은 83%가 성공합니다.
  • 매장 검색 0건의 28%는 상품 이름을 입력한 경우(‘가방’, ‘보조배터리’)입니다. 사용자는 “이 물건 어디서 파나”를 묻고 있는데 화면은 매장부터 고르게 합니다.
  • 상품 검색은 길수록 안 나옵니다. 1~2글자 33% → 10글자 이상 85%, 1단어 46% → 3단어 이상 83%. 표본에서 두 단어 이상 0건 질의의 57%는 단어 하나만 남겨도 후보가 나왔고, 띄어쓰기 제거는 효과가 없었습니다.
  • 상품 0건 표본의 42%는 다이소에 있는 상품이고 이 매장에 재고가 없을 뿐입니다(나머지 58%는 카탈로그에 없는 표현). 지금 화면은 둘 다 “검색 결과가 없습니다” 한 줄입니다.
  • 사용자는 스스로 고쳐 씁니다. 0건 뒤 검색어를 줄이면 56%가 성공하고 단어를 덧붙이면 1%만 성공합니다. 이 ‘줄이기’를 화면이 대신 해주면 됩니다.

가장 효과가 큰 개선은 ① 상품 0건의 원인 분리 + 근처 매장 재고 안내, ② 서버 쪽 질의 자동 완화(‘다이소’ 제거, 공백 정리, 단어/접미어 분해), ③ 매장 검색창에 상품명이 들어오면 상품 찾기로 연결하는 것입니다. 상세는 UX 개선안.

데이터와 방법

어떤 데이터인가

구글 시트 searches 탭의 branch(매장 검색)·product(상품 검색) 행 47,176건. 웹 UI 36,534건, API·MCP·CLI 직접 호출 10,642건. 시트의 GViz 조회 쿼리로 전량을 내려받았습니다(Ctrl+F·커넥터 읽기는 일부 행만 보이므로 쓰지 않음).

분석 대상 정리

  • 웹 검색만 사용(사용자 행동 분석). API 호출은 같은 질의를 수십~백 번 반복하는 점검성 호출이 많아 제외. 참고로 API의 0건률은 매장 26% · 상품 48%.
  • 오류(status=error) 3,096건 제외. 0건과 오류는 다른 문제입니다.
  • 9/23~9/29 상품 검색 제외. 다이소 재고 API 장애(9/30 사전 인증 복구)로 이 기간 상품 검색의 약 90%가 오류였습니다.
  • 중복 제거: 같은 (종류, 검색어, 매장)이 5분 안에 반복되면 1건으로 계산.

다이소 API 재질의(프로브)

0건 검색어 표본(상품 150개·매장 169개, 서로 다른 검색어 기준)을 다이소 공개 검색 API에 읽기 전용으로 다시 조회했습니다(약 1,000회). “상품이 카탈로그에 있는가”, “‘다이소’ 제거·공백 제거·단어 분해 시 결과가 나오는가”를 확인했고, 결과는 11/11 시점 기준입니다.

알아둘 점 로그에는 방문자 식별자가 없어서 “0건 뒤 행동”은 같은 매장에서 가까운 시각의 다음 검색으로 추정했습니다. 상품 0건의 원인(재고 없음 vs 상품 없음)도 시트에는 없어 표본 재질의로 추정했습니다. 한계는 맨 아래에 정리했습니다.

왜 이런 일이 생기나

  • 다이소 점포명은 ‘부산양정점’, ‘대구성서이곡점’처럼 지역과 동네를 붙여 쓰고 ‘다이소’는 들어 있지 않습니다. 사용자는 “다이소 홍대입구점”, “부산 양정점”처럼 말하듯 씁니다. 표본 재질의에서 ‘다이소’를 빼면 26개 중 14개가, 단어로 나눠 찾으면 23개 중 21개가 후보를 냈고, 띄어쓰기만 지워도 9개가 찾아졌습니다(예: 부산 양정점, 평택 중앙, 거제 수월).
  • 잘 되는 입력은 짧은 지명입니다. 한글 1~2글자는 0건률 17%, 성공 상위는 명동·강남·부산·동탄·홍대·신촌 같은 단어입니다. 공식 주소 문자열을 통째로 넣으면 성공하지만 “부산 해운대구 반송”처럼 줄여 쓰면 실패합니다.
  • 상품 이름을 입력하는 사람이 많습니다. 매장 검색 0건 중 28%(1,351건)입니다. 이 경우 질의를 어떻게 고쳐도 매장은 나오지 않습니다(표본 재질의에서 의미 있는 후보 3/44).
  • 영문 입력은 6%(583건)이고 98%가 실패합니다. Myeongdong·Hongdae·Sinchon처럼 관광지 로마자가 대부분이라 외국인 사용자로 보이며, 베트남어 문장 입력도 있었습니다.
  • 숫자 7자리(상품 번호)를 매장 검색에 넣는 경우가 79건, 전부 0건입니다.
추정 개선 폭 ‘다이소’ 제거 · 공백 정리 · 단어 분해만 서버에서 자동으로 해도 표본 기준 0건의 약 25%(≈1,192건)에 후보를 보여줄 수 있어, 매장 검색 0건률이 49.1% → 약 37.0%로 내려갈 여지가 있습니다. 표본이 작고 단어 일치가 곧 의도한 점포는 아니라서 상한에 가까운 값으로 보세요.

0건의 두 가지 얼굴: “상품이 없다” vs “이 매장에 재고가 없다”

서버는 카탈로그에서 상품을 찾은 뒤 이 매장 재고가 있는 것만 돌려줍니다. 그래서 0건에는 두 가지가 섞입니다. 로그에는 구분 값이 없어서(GA4에는 empty_reason이 있음) 세 가지 방법으로 추정했습니다.

① 같은 검색어를 여러 매장에서 본 경우

3개 이상 매장에서 검색된 키워드만 비교하면, 0건 4,354건 중 69%(3,008건)는 다른 매장에서는 결과가 나온 키워드(재고 편차)이고 31%(1,346건)는 모든 매장에서 0건(초코펜, 택배박스, 낚시용품, 110v 등)입니다.

② 매장별 0건률 편차

검색 60건 이상인 53개 매장의 상품 0건률은 21% ~ 69%(중앙값 41%, 상·하위 10% 57% / 27%). 같은 검색을 해도 어느 매장이냐에 따라 결과가 갈립니다.

③ 카탈로그 재조회 표본 (150개 키워드)

0건이었던 서로 다른 검색어 150개 중 63개(42%)는 다이소 카탈로그에 상품이 있음 → 재고 없음. 나머지 87개(58%)는 카탈로그에도 안 잡힘 → 표현 문제. (검색어 단위 표본이라 검색 건수 비중과는 다를 수 있음)

④ 긴 꼬리

한 번만 검색된 검색어(6,975개)의 78%가 0건입니다. 상품 0건 11,921건 중 63%(7,567건)가 3개 미만 매장에서만 검색된 희귀 표현이라, 개별 키워드를 일일이 고치기보다 규칙 기반 완화가 맞습니다.

검색어 표현 문제의 모양

  • 합성어·긴 설명은 통째로는 안 걸립니다. ‘택배박스’ 0건이지만 ‘박스’는 결과가 있습니다(‘이사박스’, ‘핀마이크’, ‘무선이어폰’도 마찬가지). 카탈로그 검색이 형태소를 나누지 않고 글자 일치에 가깝게 동작하는 것으로 보입니다.
  • 두 단어 이상 0건 표본 65개 중 23개는 재고 없음, 42개는 카탈로그 미일치였고, 후자 중 37개(88%)는 단어 하나만 남겨도 후보가 나왔습니다(마지막 단어를 뺀 경우 25개). 단어 사이 공백을 지우는 건 효과가 없었습니다(0개).
  • 오타·표기 차이가 반복됩니다: 배게→베개, 태이프→테이프, 초콜렛→초코, 임테기→임신. 같은 쌍을 서로 다른 매장에서 여러 번 고쳐 쓴 사례만 모아도 바로 쓸 수 있는 유의어·오타 사전이 됩니다.
  • 다이소가 팔지 않는 브랜드·콘텐츠(스타벅스, 햄토리, 해외 향수 이름 등)는 어떻게 해도 0건입니다. 이 경우는 “다이소에서는 취급하지 않는 것 같아요”라고 솔직히 알려주는 편이 낫습니다.
  • 7자리 품번을 검색창에 넣는 사람이 454건, 73%가 0건입니다. 상품 번호 입력은 분명한 의도(그 상품을 찾겠다)이므로 상품 상세로 바로 보내면 됩니다.

0건을 만난 사용자는 어떻게 하나

상품 검색 0건 12,374건 이후, 같은 매장의 다음 검색(10분 안)을 따라가 봤습니다.

  • 3분 안에 다음 검색에서 결과를 찾음 21.9% (2,713건)
  • 3분 안에 또 검색했지만 또 0건 38.3% (4,741건)
  • 3~10분 뒤에 다시 검색 2.0% (252건)
  • 10분 안에 후속 검색 없음 37.7% (4,668건)

성공한 검색 뒤에 후속 검색이 없는 비율은 약 53%(자연스러운 종료)인데, 0건 뒤에는 62%가 10분 안에 다시 검색합니다(60%는 3분 안). 사용자는 포기하지 않고 계속 시도하지만 4명 중 3명(76%)은 다시 0건을 만나거나 결과 없이 끝납니다. 연속으로 2회 이상 0건을 겪은 검색이 0건 전체의 59% 이상입니다(5회 이상은 5회로 계산한 하한).

UX 개선안

현재 0건 화면은 매장·상품 모두 돋보기 아이콘과 “검색 결과가 없습니다” 한 줄입니다(Search.tsx). 원인도, 다음 행동도 알려주지 않습니다. 아래 안은 “화면이 사용자 대신 시행착오를 해준다”는 한 가지 방향입니다.

0건이면 순서대로 재시도하고 어떻게 고쳐서 찾았는지 한 줄로 알려줍니다: ① ‘아성다이소·다이소·Daiso’ 제거 ② 공백 제거 ③ 단어별 검색(숫자·1글자 단어 제외, 일치한 단어를 강조) ④ 끝의 ‘점’ 제거는 효과가 없었으므로 제외. 주소 문자열(‘…시 …구 …로 12’)은 도로명·동 단어 위주로 분해.

A3. 로마자·역/지명 별칭, 위치 폴백

Myeongdong·Hongdae·Sinchon 등 상위 로마자 30~50개를 한글 지명 별칭 표로 변환하고, ‘고속터미널’·‘종각’·‘망원’처럼 점포명에 없는 지명은 지도 지오코딩 후 가까운 매장 순으로 보여줍니다(‘현재 위치로 검색’ 기능을 재사용). 영문 사용자를 위해 입력창 힌트를 “예: 명동 / Myeongdong”으로.

2순위

1순위

B1. 0건의 원인을 구분해서 말하기

지금도 스트림 응답에 scanned(훑은 상품 수)가 있어 scanned>0 → 재고 없음, =0 → 상품 없음을 이미 GA4에 보냅니다. 이를 화면 문구에 쓰기만 해도 “내 검색어가 틀렸나?”라는 혼란이 줄어듭니다. 재고 없음이면 재고 있는 가까운 매장(상품 상세에 이미 있는 근처 매장 로직 재사용)으로 연결합니다. 표본 기준 상품 0건의 약 40%가 이 경우.

1순위

B2. 검색어 자동 완화 + 칩 제안

상품이 없을 때 서버가 ① 마지막 단어 제거 ② 단어별 ③ 접미어(‘택배박스→박스’, ‘무선이어폰→이어폰’) ④ 사전 치환(배게→베개, 오뎅→어묵, 임테기→임신테스트기)을 시도하고, 결과가 있는 후보만 칩으로 보여줍니다. 칩을 누르면 바로 해당 검색. 사용자가 이미 하는 “줄이기”(성공률 56%)를 자동화하는 것입니다.

2순위

B3. 품번(7자리) → 상품 상세로 바로 이동

상품 검색창에 7자리 숫자가 들어오면 /branch/<매장>/product/<번호>로 이동(없으면 안내). 454건 중 73%가 0건이었던 구간입니다. 가장 작은 작업으로 확실한 효과.

2순위

B4. 취급하지 않는 상품 솔직하게

모든 매장에서 0건이면서 카탈로그에도 없는 질의(브랜드·콘텐츠 상품)는 “다이소에서 취급하지 않는 상품일 수 있어요. 비슷한 상품: …”으로. 현재 화면은 재시도만 유도하는 셈이라 같은 검색어 재시도 8%, 덧붙이기 1%의 헛수고를 만듭니다.

3순위

B5. 예방과 작은 개선

placeholder “상품명을 입력해주세요” → “짧게 입력해보세요 (예: 박스, 건전지)”. 0건 직후 입력창 내용을 선택 상태로 유지해 바로 고쳐 쓰게 하고, 직전 검색어를 “최근 검색”으로 제공.

측정 방법

  • 지표: 웹 검색 0건률(5분 중복 제거) 매장 49.1% → 목표 38% 이하, 상품 52.4% → 45% 이하 / 0건 후 3분 내 회복률 22% → 35% / 0건 후 10분 내 후속 검색 없음 38% → 낮추기 / 같은 검색어 재시도 비율.
  • 계측 보강(작음): 시트에 열을 추가합니다(끝에 붙이기 규칙 준수). ① 빈 결과 원인(no_match / not_in_store / relaxed), ② 완화 전 검색어, ③ 탭 세션 단위 무작위 검색 세션 ID. ③이 있으면 “0건 뒤 행동”을 추정이 아니라 정확히 셀 수 있습니다. 개인정보처리방침의 수집 항목 설명도 함께 고쳐야 합니다.
  • 롤아웃: A1·B2는 서버 완화이므로 relaxed=1 플래그로 일부 트래픽에만 켜서 0건률을 비교할 수 있습니다.

한계와 주의

  • 후속 검색은 매장 코드 + 시각 근접으로 이었습니다. 인기 매장에서는 서로 다른 사람의 검색이 섞일 수 있습니다. 매장 검색은 매장 코드가 없어 후속 행동 분석을 하지 않았습니다.
  • 입력 형태 분류는 규칙 기반입니다. ‘상품 이름’ 판정은 성공한 상품 검색어 사전에 있는지로 했기 때문에 사전에 없는 상품명은 ‘그 밖의 한 단어’로 남습니다(그 분류의 0건률은 23%로 낮아 큰 영향은 없음).
  • 다이소 API 재질의는 11/11 시점의 카탈로그·검색 동작이고 서로 다른 검색어를 무작위로 뽑은 표본(상품 150, 매장 169)입니다. 비율은 ±수 %p 오차가 있으며, ‘후보가 나온다’는 것이 ‘의도한 결과다’를 뜻하지는 않습니다. 상품 후보는 카탈로그 기준이라 이 매장 재고는 별도입니다.
  • 다이소 상류 검색 규칙은 문서화돼 있지 않아 관찰로 추정한 것입니다. 상류가 바뀌면 달라질 수 있습니다.
  • 시트는 60일 보관 정책(archiveOldRows)이 있어 이 보고서의 9/12 이후 데이터는 11/11 기준으로 일부가 월별 보관 파일로 이동할 수 있습니다. 원본 CSV는 분석 시점에 전량 내려받았습니다.
